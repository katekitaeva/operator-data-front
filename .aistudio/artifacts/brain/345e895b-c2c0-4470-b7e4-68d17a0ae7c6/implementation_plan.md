# План улучшения алгоритма подбора похожих кейсов (Шаг 2)

Реализация чистого алгоритма сходства тем по ТЗ §5.2 в отдельном модуле `js/similarity.js`, интеграция единой функции ранжирования в UI карточек и выжимку для DeepSeek, фильтрация по порогу `0.40` (топ-3), явный тай-брейк и валидация через `bun test`.

---

## 1. Выявленные проблемы текущей реализации и решения

1. **Случайный порядок и ничья (проблема порядка в массиве)**:
   - *Было*: Очки суммировались грубо (+10/+5/+4), разные кейсы («Стол», «Палатка», «Китай», «Вобла») получали одинаковый балл, а порядок определялся позицией в массиве манифеста (новые выше старых).
   - *Решение*: Нормализация путей и вычисление симметричного покрытия ($cov(A \to B)$ и $cov(B \to A)$) с учётом глубины совпадения префикса пути и бонуса за специфичность/редкость. Явный детерминированный тай-брейк:
     1. Счёт сходства (`score`, по убыванию).
     2. Наличие непустого поля «Что сработало» (`whatWorked`, приоритет заполненным кейсам).
     3. Дата кейса (`date`, ISO или `YYYY-MM-DD`, по убыванию — более свежие).
     4. Номер тикета (`ticket`, стабильная детерминированная сортировка).

2. **Неэффективный шумный бонус за слова проблемы**:
   - *Было*: Поиск слов длиннее 4 букв давал почти всем кейсам максимум очков (+3..+15) из-за частых слов («клиент», «товар», «заказ»).
   - *Решение*: Полное удаление бонуса за слова проблемы из расчета сходства тем в соответствии с ТЗ §5.2 (ранжирование строится строго на структурированной таксономии тем обращения).

3. **Отсутствие порога и показ 4-6 кейсов вместо 3**:
   - *Было*: В выдачу попадали кейсы со счётом > 0, отображалось до 6 карточек.
   - *Решение*: Строгий порог `SIMILARITY_THRESHOLD = 0.40`. Отображение максимум 3 наиболее релевантных кейсов (`slice(0, 3)`). Если подходящих кейсов нет, отображается понятное пустое состояние (без мусорных рекомендаций).

4. **Рассинхронизация выжимки для DeepSeek**:
   - *Было*: В `getSimilarDigestForDeepSeek` использовалась отдельная эвристика (+5), а при отсутствии совпадений происходил откат `(scored.length ? ... : manifestCases).slice(0, 3)`, из-за чего DeepSeek получал три случайных свежих кейса.
   - *Решение*: Использование **одной общей функции** `findSimilarCases(currentCase, manifestCases, options)` и для рендеринга карточек, и для генерации текста для нейросети. Если похожих кейсов с порогом $\ge 0.40$ нет, блок выжимки либо явно сообщает об отсутствии подходящих прецедентов, либо не подмешивает нерелевантные кейсы.

5. **Исключение дубликата текущего тикета**:
   - *Решение*: Помимо проверки `state.loadedCase.file === c.file`, добавлено строгое исключение кейсов с тем же номером тикета (`c.ticket && currentTicket && c.ticket === currentTicket`).

## 2. Архитектура и структура модулей

### Новый модуль: `js/similarity.js`
Модуль содержит чистые функции без привязки к DOM, пригодные как для запуска в браузере, так и в `bun test`:
- `normalizePath(path)`: приведение к нижнему регистру, очистка от спецсимволов/служебных меток, разбиение по `>` на массив сегментов.
- `pathSimilarity(pathA, pathB)`: расчёт схожести двух иерархических путей (глубина общего префикса, штраф за расхождение ветвей, вес более глубоких уровней классификатора).
- `computeThemeSimilarity(themesA, themesB)`: вычисление симметричного покрытия между наборами тем:
  $$\text{score} = \frac{1}{2} \left( \frac{1}{|A|} \sum_{a \in A} \max_{b \in B} sim(a, b) + \frac{1}{|B|} \sum_{b \in B} \max_{a \in A} sim(a, b) \right)$$
  с нормализацией в диапазон $[0.0, 1.0]$.
- `findSimilarCases(current, candidates, options)`:
  - Фильтрация: исключение текущего файла и совпадающего номера тикета.
  - Расчёт сходства тем.
  - Отсечение по порогу `minScore = 0.40`.
  - Сортировка по компаратору тай-брейка: `score` $\to$ `hasWhatWorked` $\to$ `date` $\to$ `ticket`.
  - Ограничение `limit = 3`.

### Рефакторинг: `js/steps/step2.js`
- Импорт `findSimilarCases` из `../similarity.js`.
- Замена алгоритма в `renderSimilarCases`:
  - Получение списка через `findSimilarCases({ themes: currentThemes, ticket: currentTicket, file: currentFile }, manifestCases, { minScore: 0.40, limit: 3 })`.
  - Обновление счётчика `#similar-counter-badge` (показывает точное число найденных кейсов выше порога).
  - Рендеринг карточек (безопасный `textContent` для пользовательских данных).
- Замена логики в `getSimilarDigestForDeepSeek`:
  - Вызов той же функции `findSimilarCases`.
  - Устранение фоллбека на `manifestCases.slice(0, 3)`.
  - Форматирование строго отобранных кейсов (или информативное сообщение о том, что прецеденты с высокой релевантностью не найдены).

## 3. План тестирования (bun test)

Создание файла тестов `tests/similarity.test.mjs` (запуск через `bun test tests/similarity.test.mjs`):
1. **Тест нормализации и попарного сходства путей**:
   - Тождественные пути дают `1.0`.
   - Полностью непересекающиеся пути дают `0.0`.
   - Вложенные категории (например, общий родитель 1-го уровня против совпадения до 3-го уровня) дают пропорциональный балл.
2. **Тест эталонных сценариев («Кошка» vs «Вобла», «Стол», «Палатка», «Китай»)**:
   - Проверка, что кейс «Вобла» занимает 1-е место со счётом $\approx 0.44 \ge 0.40$.
   - Проверка, что «Стол» ($\approx 0.30$) и «Палатка» ($\approx 0.34$) отсекаются порогом $0.40$.
3. **Тест детерминированного тай-брейка**:
   - При равном балле выше оказывается кейс с заполненным «Что сработало».
   - При равенстве обоих параметров выше оказывается более свежий по дате кейс.
4. **Тест исключения дубликатов**:
   - Кейс с тем же тикетом исключается из выдачи.
   - Кейс с тем же именем файла исключается из выдачи.
5. **Тест консистентности выжимки DeepSeek**:
   - Список кейсов в выжимке строго соответствует отображаемым карточкам.
   - При отсутствии совпадений в выжимку не попадают случайные кейсы.
