# Обновление шага 4 «Решение и тексты» (Проводник по претензии)

Превращение шага 4 в интерактивное интервью оператора с DeepSeek: автоматическое формирование состава действий, заполнение полей, сопоставление кейсов (matching) и сохранение состояния без ручной рутины.

> [!IMPORTANT]
> **Подтверждённые решения интерфейса:**
> - **Комментарий в действии «Закрыть тикет»**: единое многострочное поле со структурированными строками по частям (`1. ПРОБЛЕМА`, `2. ТРЕБУЕТ`, `3. СДЕЛАНО`, `4. ОБОСНОВАНИЕ`).
> - **Обработка незаполненных токенов в квадратных скобках (`[время звонка]`, `[N баллов]`, `[номер]` и др.)**: мягкая подсветка и предупреждающий бейдж в карточке без блокировки чекбокса «Сделано».

## 2. Пользовательский опыт и сценарии (UX Flows)

### Flow 1: Сборка промта для интерактивного интервью
1. Оператор открывает аккордеон помощника на шаге 4.
2. При нажатии «Собрать промт step003 и скопировать»:
   - Асинхронно запрашивается `cases/dictionary.json` из `operator-data` (если ещё не закэширован в сессии).
   - Из полей `fields` справочника формируется компактный блок `{{СЛОВАРЬ}}` с разметкой `(одно значение)` или `(несколько значений через запятую)`.
   - Если справочник недоступен (нет сети/токена), выводится жёлтое предупреждение «Справочник недоступен», а вместо плейсхолдера подставляется инструкция «блок МАТЧИНГ заполни вручную». Работа не блокируется.
   - Промт собирается и копируется в буфер обмена с подсказкой: *«Вставь в чат DeepSeek и отвечай на его вопросы. В конце вставь итоговый блок обратно сюда»*.

### Flow 2: Разбор итогового ответа DeepSeek
1. Оператор вставляет ответ нейросети в поле `answer4` и нажимает «Разобрать ответ».
2. Если в форме уже были изменены действия, система запрашивает подтверждение («Состояние шага 4 будет перезаписано»).
3. Валидация формата:
   - Ищется блок между последними `ИТОГ ДЛЯ ФОРМЫ` и `КОНЕЦ ИТОГА`.
   - Если границы отсутствуют или действия не распознаны: выводится сообщение об ошибке *«Попроси DeepSeek: выдай итоговый блок строго в формате»*, текущее состояние формы **не изменяется**.
4. Синхронизация действий:
   - Создаются ровно те действия, которые согласованы в блоке (`ЗВОНОК`, `ЧАТ`, `БАЛЛЫ`, `ЗАДАЧА` 1..N, `ЗАКРЫТИЕ`).
   - Действие `Темы тикета` остаётся первым, `Закрытие тикета` — последним.
   - Лишние действия (например, `Звонок`, если он не согласован) удаляются из списка.
   - Для каждого созданного действия сохраняется состояние «Сделано», если при повторном разборе такое же действие уже было выполнено.
   - Если в значениях остаются токены вида `[время звонка]`, `[N баллов]`, поле получает акцентную подсветку и выводится мягкое предупреждение.
5. Выводится сводка разбора: *«Создано пунктов: N, удалено: M, предупреждений: K»* с детализацией.

### Flow 3: Блок сопоставления кейсов (Matching)
1. Внизу экрана шага 4, над кнопкой перехода на шаг 5, отображается блок «Для сопоставления кейсов».
2. При разборе в блок построчно записываются ключи: `problemType`, `blockers`, `fault`, `demand`, `resolution`, `stage`, `essence`.
3. Система проводит проверку значений по закэшированному `dictionary.json`:
   - Значения полей `one` проверяются на строгое совпадение со списком `values`.
   - Значения полей `many` разбиваются по запятым и проверяются поэлементно.
   - Неизвестные значения подсвечиваются мягким предупреждением (*«Значение X не из справочника, поправь или поставь other»*). Переход на следующий шаг остаётся доступным.

## 3. Технические компоненты и изменения

### 3.1. Промт `prompts/step003.md`
- Замена текущего текста промта на новый эталонный текст интерактивного интервью с 4 этапами (ВАРИАНТЫ, СПИСОК ДЕЙСТВИЙ, РАЗБОР ДЕЙСТВИЙ, ИТОГ ДЛЯ ФОРМЫ) и 4 плейсхолдерами: `{{ФАКТЫ}}`, `{{КОНТЕКСТ}}`, `{{ИНСТРУКЦИИ}}`, `{{СЛОВАРЬ}}`.

### 3.2. Загрузка и кэширование словаря (`js/steps/step4.js` & `js/config.js`)
- Использование существующей константы `DICTIONARY_PATH = "cases/dictionary.json"`.
- Функция `loadDictionary()`: сессионное кэширование (в памяти модуля / sessionStorage), парсинг `fields`, фильтрация блоков `weights`, `client`, `genericInstructionBlocks`.
- Функция `formatDictionaryForPrompt(dict)`: форматирование по шаблону ТЗ.
- Сохранение `dict.version` в состоянии для matching.

### 3.3. Модель данных и карточки действий (`js/steps/step4.js`)
- Расширение типов действий:
  - `themes` — добавление тем из шага 2 (остаётся первым).
  - `call` — «Звонок клиенту» (поля: `time`, `script`, `done`, `open`).
  - `chat` — «Ответить клиенту в чате» (поля: `text`, `done`, `open`).
  - `compensation` — «Начислить баллы / согласовать компенсацию» (поля: `compType`: баллы|компенсация, `points`, `reason`, `approval`, `done`, `open`).
  - `task` — «Задача» (поля: `target`: отдел или CTASK, `text`, `taskNo`: номер задачи со ссылкой на CRM, `done`, `open`). Поддержка произвольного числа задач.
  - `comment` (или `service`) — «Закрыть тикет с комментарием» (поля: `commentText`, `done`, `open`).
- Обновление библиотеки добавления действий (`btn-add-action` с селектом доступных типов действий: звонок, чат, баллы, задача, закрытие).

### 3.4. Парсер итогового блока (`js/parser.js` или специализированный парсер в `step4.js`)
- Функция `parseStep4FinalAnswer(rawText)`:
  - Извлечение последнего блока между `ИТОГ ДЛЯ ФОРМЫ` и `КОНЕЦ ИТОГА`.
  - Устойчивая нормализация (удаление markdown-звёздочек, полноширинных двоеточий, пробелов, префиксов).
  - Разбор действий: `ЗВОНОК`, `ЧАТ`, `БАЛЛЫ`, `ЗАДАЧА` (множественные), `ЗАКРЫТИЕ`.
  - Извлечение блока `МАТЧИНГ` (ключи `problemType`, `blockers`, `fault`, `demand`, `resolution`, `stage`, `essence`).
  - Обнаружение токенов в квадратных скобках `[...]`.

### 3.5. Сохранение состояния в `js/state.js` и `localStorage`
- Сохранение массива `state.actions` с полной структурой полей, порядком, флагами `done` и `open`.
- Сохранение `state.matchingText` и `state.dictionaryVersion` (а также привязка к существующему `FIELDS` / `STORAGE_KEY`).
- Обратная совместимость при вызове `load()`: если состояние создано в старой версии и в `actions` отсутствует действие «Звонок клиенту», оно автоматически добавляется на вторую позицию.

## 4. План верификации и приёмки

1. **Сборка промта**:
   - Проверить подстановку всех 4 плейсхолдеров (`{{ФАКТЫ}}`, `{{КОНТЕКСТ}}`, `{{ИНСТРУКЦИИ}}`, `{{СЛОВАРЬ}}`).
   - Проверить graceful fallback при отключенном подключении к GitHub (предупреждение «Справочник недоступен»).
2. **Парсинг эталонного ответа (Приложение 10)**:
   - Вставить эталонный блок из ТЗ.
   - Проверить создание действий: Звонок, Чат, Баллы, Задача 1, Задача 2, Закрытие.
   - Проверить корректность заполнения полей, ссылок CRM и блока matching.
3. **Граничные условия**:
   - Блок без «ДЕЙСТВИЕ: ЗВОНОК» — пункт звонка удаляется.
   - Неизвестное значение в matching (`item_mismach`) — отображается мягкое предупреждение без блокировки навигации.
   - Повторный разбор — запрос подтверждения, перенос выполненных отметок «Сделано».
   - Перезагрузка страницы (`F5`) — полное сохранение состава, порядка, текстов, чекбоксов и matching.
4. **Линтинг и компиляция**:
   - Запуск `lint_applet` и `compile_applet`.
   - Проверка консоли браузера на отсутствие ошибок.
